# 授权与打包落地方案

不自建服务器、不做在线集中校验。私钥只在作者电脑，公钥随程序发布；程序必须联网（游戏本身要求），因此公共 NTP 作为默认可信时间源，**首次激活必须联网**取得多源时间共识。

## 1. 与主程序的三条契约（零侵入）

| 契约 | 内容 |
|---|---|
| 入口 | 打包入口用 `launcher.py`，**不改 `game_bot.py` 任何一行**。旧的 `build_exe.bat` 与 `run.bat` 都已标注 `[DEPRECATED]`，其产物/入口不含授权，禁止对外发布 |
| 工作目录 | frozen 时 launcher 先算好模板绝对路径、再把 CWD 切到 `%APPDATA%\ShootAtZombies`，解决 `config.json` 与 `screenshots` 相对路径写不了 |
| 资源路径 | 以 `templates/` 是否真实存在为判据补齐 `sys._MEIPASS`；Nuitka 下额外尝试 onefile 临时目录并在需要时设 `sys.frozen = True` 以对齐主程序。找不到会写 `startup_error.log`、弹窗提示并拒绝启动 |

`templates/` 增删、游戏逻辑改动都不影响授权层。看门狗退出时会调用 `GameBotGUI.quit_app()`，让机器人线程与 stdout 重定向正常收尾。

## 3. 许可证模型

`type=perpetual`（买断，不做任何时间校验） / `type=timed`（固定秒数） / `type=revoke`（撤销令）。

| 字段 | 含义 |
|---|---|
| `v` / `app` | 格式版本、产品标识 |
| `order` / `nonce` / `seq` | 订单号、防重放、**续期递增序号**（旧许可不能重置计时） |
| `mid` / `fp[]` / `min_match` | 机器码、组件哈希、至少匹配 2~3 项（客户端强制下限） |
| `iat` / `activate_before` | 可信时间签发 / 签发后 7 天内必须激活（防转发主力） |
| `duration_seconds` | 限时秒数，1 月 = 30 天固定秒数 |
| `target_order` / `reason` / `challenge` | 撤销令专用，challenge 用于复算退款回执 |

许可证与撤销令都走严格 schema：整数只接受 `int`（拒绝 `bool`、`float('inf')`、超 2^63 值），`fp[]` 只接受 8~64 位十六进制字符串。畸形 payload 一律拒绝，不会抛异常。

**限时到期的三重判据**：

1. 日历时间：`effective_now > activated_at + duration_seconds`，其中 `effective_now = max(now, high_water)`；
2. 累计运行时长：心跳用 `time.monotonic()` 累加 `used_seconds`，`used_seconds >= duration` 或 `used_seconds > (effective_now - activated_at) + 3600` 判定失效；
3. 回拨：`now` 落后 `high_water` 超过 10 分钟即拒绝。

`high_water` 是状态里**只增不减**的历史最晚可信时间，只在「NTP 共识 + 本地时钟方向交叉校验」通过时上调，自愈可以下调 `last_seen` 但绝不能下调它。第六轮 B-1 曾发现：客户激活后只用了几小时就长期不开程序时，`last_seen` 严重滞后、`used_seconds` 远小于日历时长，单靠前两条判据可被「阻断 NTP + 把本地时间回拨到到期前」复活已过期许可。现在 `effective_now` 不能被更小的 `now` 抹掉，且 `timed` 每次启动强制校时。看门狗与心跳都走 `state_store.update_state()` 原子读-改-写。

## 4. 可信时间设计（第六轮 review 后重写）

| 规则 | 原因 |
|---|---|
| **NTP 共识至少 2 个可用样本，且每个样本与中位数偏差 ≤30 秒** | 第五轮 H-2：旧实现用「极差 ≤1 天」，控制 2/3 源并把时间偏移 20 小时即可成为共识。现在任何样本偏离中位数超过 30 秒，本轮共识直接失败 |
| **非对称交叉校验**：网络时间领先本地时钟不限；网络时间落后本地时钟 >2 天则不采信 | 系统时钟慢 40 天的诚实客户仍应拿到 NTP 真值；反过来「往回拨」是唯一能延长限时的方向，必须由本地时钟兜住。攻击者同时把本机时间也调回过去，才落入已接受的「全源 NTP 控制且持续调回本地时间」边界 |
| 远期投毒上界只相对「状态高水位 / 已验证缓存」 | 一次远期投毒会把 `last_seen` 抬到多年后，之后诚实 NTP 反被当倒退拒绝。无锚无缓存（首次运行）时采信 NTP，它是唯一权威 |
| 多源一致落后于锚时下调锚自愈，但不下调状态里的 `high_water` | 本地时钟曾被调快造成的历史污染不能让客户永久锁死；同时必须保住不可回拨的到期下界（第五轮 H-1） |
| **首次激活 + 作者端签发都 fail-closed**：`activate()` / `require_trusted_now()` 要求本轮 NTP 共识与交叉校验 | 客户端首次激活拒绝，作者端却用偏移的本地时钟写 `iat`，会让付费客户被「系统时间早于签发时间」拒之门外（第五轮工程 H1） |
| **`timed` 每次启动严格校时**：`ensure_license()` 走 `check_license(strict_time=True)`，无可信时间直接拒绝 | 关掉 B-1 的「断 NTP + 回拨」复活路径。游戏本来就联网；`perpetual` 不做任何时间校验，看门狗每 60 秒的复查不严格校时、靠 `high_water` 防止运行中回拨 |
| 激活时 `now + 1 小时 >= iat`，且 `now <= activate_before` | `iat` 是作者端可信时间签发的、客户改不了的时间下界；1 小时容差覆盖作者/客户端小时级偏差 |
| **锚绝不用于抬高 `trusted_now()`** | 旧实现 `max(local, anchor)` 让 `last_seen - now > 600` 恒成立，回拨检测被架空 |
| **只在 `time_is_cross_checked()` 时写 `last_seen` / `high_water`** | NTP 全断 + 本地时间被调快 40 天时，绝不把高水位污染到远期；`time_is_trusted()` 只说明「来自某轮共识」，投毒共识也算，不能单独放行写盘 |
| 启动同步预热一次，之后后台 300 秒刷新 + 失败退避 300 秒 | `trusted_now()` 缓存有效时**永远只做内存计算**。主线程只在启动预热、首次激活、作者端签发三处做一次网络 I/O；激活窗口会先刷新「正在校准网络时间」提示 |
| 看门狗对「回拨 / 校准 / 联网」类失败最多豁免 10 tick | 不能无限豁免让已到期程序一直跑；退出后置停机闩，残留 `after` 回调不得重复调用 `quit_app()` |

跨重启回拨：缓存冷 + NTP 被阻断时返回原始本地时间并标记不可信；`timed` 启动严格校时直接拒绝，`perpetual` 不受影响。

## 5. 状态封装密钥与指纹锚（覆盖安装免重新授权的关键）

状态用构建期注入的随机密钥做 HMAC-keystream XOR + MAC 封装。密钥一旦变化，老客户 `state.json` 解不开 → 变成「尚未激活」→ 但 `activate_before` 早已过期 → **连重新激活都做不到**，只能逐单人工重签。这是付费分发下最严重的事故，因此加了三层护栏：

1. `licensing/state_secret.fingerprint` 是**受版本控制的指纹**（不是密钥），随源码提交；
2. `keygen init-state-secret` 在备份缺失且锚已存在时**直接报错**，绝不静默随机生成；备份与锚不一致也报错；
3. `build_release.py --check` 同时校验：`state_secret.py` 格式、与 `keys/state_secret.txt` 一致、与指纹锚一致、产物中无敏感文件；任一不满足拒绝构建。

换构建机的正确流程：先把 `licensing/keys/state_secret.txt`（和 `private.json`）从离线备份拷回，再运行 `init-state-secret`。

## 6. 作者端操作

```bash
# 只做一次！生成密钥对、公钥模块、状态密钥与指纹锚。
# 已有 private.json 时会直接拒绝，避免手滑作废全部已发许可；确需重建才加 --force
python -m licensing.keygen init

# 换构建机：先拷回离线备份 keys/state_secret.txt，再恢复/登记（不动 RSA 密钥对）
python -m licensing.keygen init-state-secret

# 客户发来 activation_request.txt（激活窗口内导入）
python -m licensing.keygen sign --request-file activation_request.txt --type timed --days 7 --order A001 --out A001.lic
python -m licensing.keygen sign --request-file activation_request.txt --type perpetual --order P001 --out P001.lic

# 续期：复用台账机器码，客户不用再发机器码，seq 自动 +1
python -m licensing.keygen renew --order A001 --days 30 --out A001-renew.lic

# 退款：生成撤销令发给客户，导入后程序停用并弹出回执
python -m licensing.keygen revoke --order A001 --reason "用户退款" --out A001-revoke.lic
python -m licensing.keygen verify-receipt --order A001 --code <回执码> --at <回执上的Unix秒>

python -m licensing.keygen list       # 查台账
python -m licensing.keygen ui        # 轻量 GUI（推荐，自动记台账）
```

**退款流程**：客户导入撤销令 → 回执窗口（订单号 / 机器码 / UTC 时间 / Unix 秒 / 回执码）模态显示 → 客户**连续录屏**（从导入前到回执显示）→ 你用 `verify-receipt` 复算 → 人工核对 → **延时放款**。回执是流程性证据，见第 9 节。

## 7. 客户端流程

- **首次启动**：弹出激活窗口，显示机器码与激活请求；客户复制发你，你签发 `.lic`，客户粘贴或导入。**首次激活必须联网**（NTP 共识 + 交叉校验），否则明确提示「请校准时间或联网后重试」；激活按钮会先显示「正在校准网络时间」。
- **日常启动**：`check_license(strict_time=True)` 校验（签名 + 机器指纹 + seq + 时间 + 累计时长 + 单调 `high_water` + 撤销状态）。**限时版每次启动都要联网校时**，NTP 不可达会拒绝并提示；买断版不校验时间。公钥指纹与状态密钥模块自检在 `launcher.py` 单独执行，失败写 `startup_error.log` 并弹窗。
- **运行中**：每 60 秒复查一次，连续 3 次**非时间校准类**失败才退出；「回拨/校准/联网」类失败最多豁免 10 个 tick（10 分钟），退出前调用 `GameBotGUI.quit_app()`，并置停机闩防止残留 `after` 回调重复退出。到期或撤销令生效不依赖用户重启。
- **更新**：直接覆盖安装，`[Files]` 白名单只收 `ShootAtZombies.exe` 与 `_internal\`，状态在 `%APPDATA%` + HKCU，**不需要重新授权**。`AppId` 永远固定，`AppVersion` 递增，`[UninstallDelete]` 保持留空。
- **撤销令投递**：**交付流程只有一种**——退款时让客户在激活窗口导入 `.revoke` 并截图/录屏。客户端也会扫描 `{app}\revocations\` 与 `%APPDATA%\ShootAtZombies\revocations\`，但那需要作者另行手工投递文件到那台机器；安装包 `[Files]` 白名单**不自动下发**任何撤销令，因此「放进目录就会自动作废」不是交付承诺。

## 8. 打包与发布

```bash
python -m pip install pyinstaller
python -m licensing.keygen init-state-secret # 换机构建 / 干净 checkout：先恢复备份再执行
python packaging/build_release.py --check   # 发布前检查（含引擎可用性、产物敏感扫描）
python packaging/build_release.py --engine pyinstaller
# 用 Inno Setup 编译 packaging/installer.iss → dist/installer/ShootAtZombiesSetup.exe
python packaging/verify_release.py          # 真实流程冒烟
```

**内置运行环境与 OCR**：产物是 **PyInstaller onedir**（`ShootAtZombies.exe` + `_internal\`），不依赖客户机装 Python——`python313.dll`、`python3.dll`、VC++ 运行库（`vcruntime140*.dll`、`msvcp140*.dll`）都在 `_internal\`。新版 `game_bot.py` 用 `rapidocr-onnxruntime` 做 OCR 选技能，构建通过 `--collect-data rapidocr_onnxruntime` 把 `config.yaml` + 3 个 `.onnx` 模型（约 13.7M）打进 `_internal\rapidocr_onnxruntime\`，PyInstaller 运行时按模块的 `__file__` 定位到该目录。**这部分是数据文件，PyInstaller 静态分析不会自动收集**，必须靠 `--collect-data`；缺了它客户机首次 `RapidOCR()` 会抛 `FileExistsError`。发布前检查 `ocr_resource_problems()` 会校验源环境模型齐全，`dist_problems()` 只对该目录放行 `.onnx`/`.yaml`，塞 `.py` 仍会被拦。完整产物约 259M（`cv2` 126M + `onnxruntime` 45M 是大头）。

`--check` 校验：`templates/`、`launcher.py`、私钥、公钥 `FINGERPRINT` 与 `N` 自洽、`state_secret.py` 格式、与 `keys/state_secret.txt` 一致、与指纹锚一致、**指纹锚确实在 git HEAD 里（仅暂存不算；这条是 `[WARN]` 提示，不阻断构建，交付前必须人工消除）**、`dist/` 反向白名单扫描（改名/非常规后缀的私钥、台账、日志、客户名单都拦得住）、PYZ 内状态密钥与备份一致、当前引擎工具可用。构建前清空 `dist/ShootAtZombies/`，构建后再扫一次产物；Nuitka 档位也会做同样的产物扫描。

**默认且唯一实测通过的是 PyInstaller onedir**（约 201M，115 张模板，PYZ 内含 `licensing.state_secret` 且与备份一致、不含 `licensing.keygen*`）。`state_secret.py` 通过顶层静态导入 + `--hidden-import` 双重保证被收进产物。

**Nuitka 是实验性、未验证档位**：onefile 的数据目录与 `sys._MEIPASS` 语义不同，必须在干净虚拟机实测 `templates` 能加载后才能用于正式交付；`installer.iss` 的白名单也按 PyInstaller 结构编写。切到 Nuitka 并实测通过后，才做「pyinstxtractor 提取不到明文业务代码」的加固验收。公钥本来就是公开的，常量明文不影响安全；要防的是验签分支被打补丁。

VC++ 运行库：PyInstaller 通常自带 `vcruntime140.dll`，是否需要捆绑 `vc_redist.x64.exe` 以干净虚拟机实测为准，`installer.iss` 里已留好注释位置。

## 10. 架构限制（必须知道，不是 bug）

| 限制 | 说明 | 缓解 |
|---|---|---|
| **回执不能证明「导入过」** | 客户端没有私钥，回执码的所有输入客户都能自行算出，完全不导入也能伪造有效回执截图 | 连续录屏 + 人工核对 + 延时放款；不要仅凭截图退款 |
| **本地状态不是绝对可信** | 状态用构建期注入的随机密钥密文封装，改 JSON 字段已失效，但逆向二进制仍可提取密钥伪造状态 | 编译加固 + 启动自检 + 缩短激活窗口；接受「专业级仍可绕」 |
| **删干净双份状态 + 窗口内重导入** | 文件与注册表都被删除后，在 7 天激活窗口内重导入同一张许可可重置一次计时 | 双副本 + 密文 + 台账人工发现异常；根治必须在线激活 |
| **首次激活 / 限时版日常启动依赖公共 NTP 可用** | 企业防火墙全拦 UDP/123 的客户无法首次激活，限时版也无法启动 | 明确提示联网/校时；买断版不受影响；必要时作者可临时放行或改用离线人工时间核对流程 |
| 替换公钥 + 自签 | 公钥与指纹在同一个随包文件里，一起改就能自洽；`public_key_is_consistent()` 只防误改不防恶意替换 | 属于「打补丁」类，靠编译加固抬成本 |

其他已确认接受的边界：

| 场景 | 防御 | 残余 |
|---|---|---|
| 改系统时间（回拨 / 冻结） | NTP 秒级共识 + 非对称交叉校验 + 单调 `high_water` + `last_seen` 回拨检测 + 心跳 `used_seconds` | 同时控制全部 NTP 响应**且**持续把本地时间也调回过去，属已接受的专业级上限；`high_water` 让「只改一个」不再有效 |
| 阻断 NTP / 误杀诚实 NTP | 首次激活、`timed` 每次启动、作者端签发都 fail-closed；不可信时间不写任何高水位 | **限时版断网不可用**（游戏本身需联网的产品决策）；买断版不受影响 |
| 一次性远期 NTP 投毒 | 相对锚/缓存的 30 天上界；极端倒退多源一致且与本地时钟一致时下调锚自愈，但不动 `high_water` | 已接受的「全源投毒」专业级场景 |
| 间歇使用下到期复活 | `effective_now = max(now, high_water)` + 启动严格校时 | 见上一行 |
| 反复导入同一张许可 | `seq` 递增，只接受更大 | 整盘状态回滚时失效 |
| 发给朋友 / 克隆整机 | 机器指纹 + 激活窗口 + 台账 | 硬件完全相同的克隆机可能撞码 |
| 打补丁跳过校验 | 编译加固 + 公钥自检 + 启动看门狗 | 只能抬成本 |
| 整盘快照回滚 / 硬件克隆 / 破解版扩散 | 无服务器下无法根治 | **已接受** |

不发新版、客户不导入撤销令时，老客户端会一直跑到 `timed` 到期（买断版则一直跑）——这是无服务器方案的上限。

## 11. 私钥与密钥管理（最重要）

- `licensing/keys/private.json`、`licensing/keys/state_secret.txt`、`licensing/state_secret.py` 都已忽略，**绝不提交、绝不放进安装包**；`licensing/state_secret.fingerprint` 只是指纹，**必须提交到 git HEAD**（`--check` 用 `git cat-file -e HEAD:` 校验，仅 `git add` 暂存会打印 `[WARN]`）。
- 立刻离线备份 `private.json` 与 `state_secret.txt`（U 盘 / 密码管理器）。私钥丢失：无法再签发/续期/撤销；状态密钥丢失或换值：老客户状态解不开，且激活窗口已过，必须逐单重签。
- 换构建机：先拷回备份，再 `init-state-secret`；**不要重新随机生成**。`--check` 会比对指纹锚，不一致直接拒绝构建。
- **不要再运行 `keygen init`**：已有私钥时命令会直接拒绝；`--force` 会重建 RSA 密钥对并作废所有已发许可。`init-state-secret` 不动 RSA 密钥对。
- 公钥指纹：`b69c54cf17c98a54`；客户端启动自检，发布前 `--check` 还会校验指纹与 `N` 自洽。
- 台账 `orders.jsonl` 含所有客户机器指纹与撤销 challenge，等同客户资料，需加密备份、不要随包分发。
- 干净 checkout 里没有 `state_secret.py` 时，程序会用公开的 DEV-ONLY 派生密钥运行（仅供开发/测试）；`--check` 会拦住这种状态，不允许发布。

## 12. 默认值速查

激活窗口 7 天 · 首次激活、作者端签发、**限时版每次启动**都必须联网（NTP ≥2 源、每样本与中位数偏差 ≤30 秒、非对称交叉校验）· `min_match` 客户端强制 2~3 · NTP 三源并发 + 30 天远期上界/2 天过去方向容差 + 启动预热 + 后台刷新 300 秒 + 失败退避 300 秒 · 状态双副本密文 + 原子更新 + IO 锁 + 单调 `high_water` + 指纹锚（必须在 git HEAD）· `perpetual` 不做时间校验 · `timed` 日历（以 `high_water` 为下界）+ 累计运行时长 + 回拨三判据（1 小时容差）· 换机重签由作者按台账人工判断 · 到期靠 `seq+1` 续期 · 1 月 = 30 天固定秒数 · 看门狗 60 秒 / 连续 3 次非时间校准类失败退出 / 时间校准类最多豁免 10 tick / 退出后停机闩生效 · 台账 `orders.jsonl`。
